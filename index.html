1. Előfeltételek & Bejelentkezés

  • Regisztráció: aws.amazon.com
  • Free Tier feltételek: Max. 6 hónapig és azon belül 700 óra használat ingyenes.
  • Mindig a Free tier eligible címkével ellátott erőforrásokat válaszd!
  • Gyakorlás után: Mindig töröld le a létrehozott erőforrásokat, hogy ne fogyassza a keretet.
  • 2FA: Állítsd be a kétfaktoros hitelesítést regisztráció után!

Bejelentkezés lépései:

  • Kattints a Sign in to Console gombra.
  • Válaszd a Sign in with root user email opciót.
  • Végezd el a 2FA azonosítást.
  • RÉGIÓ FONTOS: A jobb felső sarokban mindig Europe (Frankfurt) / eu-central-1 legyen kiválasztva!

2. Hálózat létrehozása és beállítása (VPC, Subnet, IGW, Route)

a) VPC létrehozása

  • AWS Kereső: VPC
  • Bal oldali menü: Your VPCs
  • Jobb felső sarok: Create VPC
  • Name tag: NEPTUN-vpc-1
  • IPv4 CIDR: 10.0.0.0/24
  • Nyomj rá a Create VPC gombra.

b) Alhálózatok (Subnets)

3 darab subnetet hozunk létre a 10.0.0.0/24 CIDR tartományon belül:

  • Bal oldali menü: Subnets ➔ Create subnet
  • VPC ID: Válaszd ki a sajátodat (NEPTUN-vpc-1)
  • Hozz létre 3 alhálózatot az Add new subnet gombbal:
    • 1. Subnet: Name: NEPTUN-subnet-1 | AZ: eu-central-1a | CIDR: 10.0.0.0/25
    • 2. Subnet: Name: NEPTUN-subnet-2 | AZ: eu-central-1b | CIDR: 10.0.0.128/26
    • 3. Subnet: Name: NEPTUN-subnet-3 | AZ: eu-central-1c | CIDR: 10.0.0.192/26
  • Kattints a Create subnet gombra.
Automata IP kiosztás (DHCP) beállítása:
A létrehozott subneteket egyesével jelöld ki a listában ➔ Actions ➔ Edit subnet settings ➔ Pipáld be: Enable auto-assign public IPv4 address ➔ Save

c) Internet Gateway (IGW)

  • Bal oldali menü: Internet gateways ➔ Create internet gateway
  • Name tag: NEPTUN-igw-1 ➔ Create internet gateway
  • Jelöld ki a listában az IGW-t ➔ Actions ➔ Attach to VPC
  • Válaszd ki a saját VPC-det (NEPTUN-vpc-1) ➔ Attach to VPC

d) Route Tables

  • Bal oldali menü: Route tables ➔ Create route table
  • Name: NEPTUN-rtb-1 | VPC: Saját VPC kiválasztása ➔ Create route table
  • A létrejött route tábla részleteinél: Edit routes ➔ Add route
  • Destination: 0.0.0.0/0 | Target: Internet Gateway (kiválasztva a NEPTUN-igw-1-et)
  • Nyomj rá a Save changes gombra.

3. Security Group (Biztonsági Csoport) Beállítása

  • Bal oldali menü: Security groups
  • Válaszd ki azt a Security Group-ot, ami a saját VPC-dhez jött létre.
  • Az Inbound rules fülön kattints az Edit inbound rules gombra.
  • Add hozzá az alábbi szabályokat (Add rule):
    • SSH: Port 22 | Source: Anywhere-IPv4 (0.0.0.0/0)
    • HTTP: Port 80 | Source: Anywhere-IPv4 (0.0.0.0/0)
    • HTTPS: Port 443 | Source: Anywhere-IPv4 (0.0.0.0/0)
    • MySQL/Aurora: Port 3306 | Source: Custom (10.0.0.0/24)
  • Mentés: Save rules

4. Adatbázis és Szerverek Létrehozása

a) RDS MySQL Adatbázis Szerver

  • AWS Kereső: RDS ➔ Create database
  • Creation method: Standard create (Full configuration)
  • Engine type: MySQL
  • Credentials Settings:
    • Master username: api
    • Master password: 12345678
  • Connectivity:
    • Virtual Private Cloud (VPC): NEPTUN-vpc-1
  • Kattints a Create database gombra.
Megjegyzés: Az adatbázis elindulása perceket vesz igénybe. Amíg készül, a felső sávban kattints a View connection details gombra, mert az Endpoint URL-re szükséged lesz az API szerver beállításánál!

b) API Szerver (EC2) Létrehozása

  • AWS Kereső: EC2 ➔ Instances ➔ Launch instances
  • Name and tags: NEPTUN-ec2-api
  • OS Image: Ubuntu (Free tier eligible)
  • Key pair: Válaszd ki a meglévő kulcsot vagy hozz létre újat.
  • Network settings ➔ Edit:
    • VPC: NEPTUN-vpc-1
    • Subnet: NEPTUN-subnet-1
    • Security group: Válaszd ki a VPC-dhez tartozó meglévő csoportot.
  • Advanced details ➔ User data: Töltsd ki az alábbi szkripttel (Írd át a MYSQL_DOMAIN és NEPTUN változókat!):
#!/bin/bash
# variables
NEPTUN="NEPTUN"                                                      # A te Neptun kódod
MYSQL_DOMAIN="neptun-db.xxxx.eu-central-1.rds.amazonaws.com"        # RDS Mysql Endpoint URL

apt update
apt install wget unzip python3 python3-pip python3-flask -y
apt install python3-mysql.connector -y

# get code
mkdir /tmp/code
cd /tmp/code
wget https://wiki.farkas-attila.hu/images/c/c7/Weboldal.zip
unzip Weboldal.zip

# change <ip> tag in code
sed -i "s/<ip>/$MYSQL_DOMAIN/g" api.py

# create directory for server
mkdir -p /srv/$NEPTUN
mv api.py /srv/$NEPTUN/

# remove tmp directory
cd /
rm -rf /tmp/code

echo "@reboot root sleep 10s && python3 /srv/$NEPTUN/api.py &" >> /etc/crontab
cd /srv/$NEPTUN && nohup python3 api.py > api.log 2>&1 &

Indítás: Launch instance

c) UI Szerver (EC2) Létrehozása

  • EC2 ➔ Instances ➔ Launch instances
  • Name and tags: NEPTUN-ec2-ui
  • OS Image: Ubuntu (Free tier eligible)
  • Network settings ➔ Edit:
    • VPC: NEPTUN-vpc-1
    • Subnet: NEPTUN-subnet-2
    • Security group: Meglévő biztonsági csoport kiválasztása.
  • Advanced details ➔ User data: Töltsd ki az alábbi szkripttel (Írd át az API_LB_DOMAIN és NEPTUN változókat!):
#!/bin/bash
export DEBIAN_FRONTEND=noninteractive

# variables
NEPTUN="NEPTUN"                                  # A te Neptun kódod
API_LB_DOMAIN="10.0.0.xxx"                      # Az API szerver publikus/privát IP címe

apt-get update
apt-get install -y wget unzip apache2 php libapache2-mod-php php-curl

# get code
mkdir -p /tmp/code
cd /tmp/code
wget https://wiki.farkas-attila.hu/images/c/c7/Weboldal.zip
unzip -o Weboldal.zip

# change <ip> tag in code
sed -i "s/<ip>/$API_LB_DOMAIN/g" ui.php
sed -i "s/<ip>/$API_LB_DOMAIN/g" ui_newproduct.php

# create directory for server
mkdir -p /srv/$NEPTUN
mv ui.php /srv/$NEPTUN/index.php
mv ui_newproduct.php /srv/$NEPTUN/newproduct.php

# remove tmp directory
cd /
rm -rf /tmp/code

cat << EOF > /etc/apache2/sites-enabled/000-default.conf
<VirtualHost *:80>
	ServerAdmin webmaster@localhost
	DocumentRoot /srv/$NEPTUN
	<Directory /srv/$NEPTUN/>
		Options Indexes FollowSymLinks
		AllowOverride None
		Require all granted
	</Directory>
	ErrorLog \${APACHE_LOG_DIR}/error.log
	CustomLog \${APACHE_LOG_DIR}/access.log combined
</VirtualHost>
EOF

systemctl restart apache2

d) Adatbázis inicializálása az API szerverről

  • Lépj a Instances menüpontba ➔ Jelöld ki az NEPTUN-ec2-api szervert ➔ Connect
  • A konzolban telepítsd a MySQL klienst: 
    sudo apt install mysql-client -y
  • Csatlakozz az RDS adatbázishoz (a [HOST] helyére az RDS Endpoint-ot másold!): 
    mysql -h[HOST] -uapi -p12345678
  • Futtasd az alábbi adatbázis-séma szkriptet a MySQL parancssorban:
create database if not exists electric;
use electric;

CREATE TABLE products (
  id int AUTO_INCREMENT primary key,
  name varchar(100),
  type varchar(20),
  value varchar(20),
  price decimal(10,2),
  created_at timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

insert into products set name="ESP-32", type="MPU", value="32bit", price=1800.66; 
insert into products set name="STM32F407", type="MPU", value="32bit", price=3500;
insert into products set name="STLink", type="Tool", value="", price=500.15;

create user 'api'@'%' identified by '12345678';
grant all on electric.* to 'api'@'%';
quit;
Működési ellenőrzés: Nyisd meg a UI szerver publikus IP címét a böngészőben (strictly HTTP protocol!). Ha a terméklista betölt, az infrastruktúra első része hibátlanul működik!

5. Skálázhatóság (AMI, Launch Template, Auto Scaling, Load Balancer)

a) AMI (Amazon Machine Image) Létrehozása

  • Bal menü: Instances ➔ Jobb klikk a NEPTUN-ec2-ui szerveren.
  • Válaszd: Image and templates ➔ Create image
  • Image name: NEPTUN-ui-ami
  • Nyomj rá a Create image gombra.

b) Launch Template Létrehozása

  • Jobb klikk a NEPTUN-ec2-ui szerveren ➔ Image and templates ➔ Create template from instance
  • Name: NEPTUN-ui-tmp
  • Application and OS Images (AMI): Válaszd ki a My AMIs fület, majd a NEPTUN-ui-ami-t!
  • Kattints a Create launch template gombra.

c) Auto Scaling Group & Load Balancer Felépítése

  • Bal menü: Auto Scaling Groups ➔ Create Auto Scaling group
  • Name: NEPTUN-ui-asg | Launch template: NEPTUN-ui-tmp ➔ Next
  • VPC: NEPTUN-vpc-1 | Subnets: Pipáld ki mind a 3 subnetet! ➔ Next
  • Load balancing:
    • Válaszd: Attach to a new load balancer
    • Scheme: Internet-facing
    • Listeners and routing (Default routing): Válaszd a Create target group opciót!
    • Target group name: NEPTUN-ui-asg-tg ➔ Next
  • Group size & Scaling policies:
    • Min desired capacity: 1 | Max desired capacity: 3
    • Scaling policy: Target tracking scaling policy
    • Instance warmup: 60 sec ➔ Next ➔ Next ➔ Create Auto Scaling group
Integráció ellenőrzése / csatlakoztatása:
Kattints az elindult Auto Scaling Group-ra ➔ Integrations fül ➔ Load balancing részben Edit ➔ Pipáld be: Application, Network or Gateway Load Balancer target groups ➔ Válaszd ki a NEPTUN-ui-asg-tg-t ➔ Update

6. Tesztelés & Stressz Teszt

a) Load Balancer Weboldal Teszt

  • Bal menü: Load Balancers ➔ Kattints a létrejött Load Balancer-re.
  • Keresd meg a DNS name mezőt, és másold ki az URL-t.
  • Nyisd meg egy új fülön HTTP-n keresztül. Ha betölt a weboldal, az ALB megfelelően továbbítja a kéréseket.

b) Stressz Tesztelés (Automatikus Skálázás Céljából)

  • Bal menü: Target Groups ➔ Kattints a NEPTUN-ui-asg-tg célcsoportra. (Healthy státuszú gépek száma kezdetben: 1).
  • Bal menü: Instances ➔ Jelöld ki az Auto Scaling Group által legutoljára elindított UI példányt ➔ Connect.
  • Telepítsd és futtasd a CPU megterhelő eszközt: 
    sudo apt update && sudo apt install stress -y
stress --cpu $(nproc) --timeout 300
  • Ellenőrzés: Várj kb. 1-2 percet. Lépj vissza a Target Groups felületére, és ellenőrizd, hogy a **Healthy** gépek száma 1-ről 2-re (vagy 3-ra) emelkedett-e!

7. Erőforrások Teljes Törlése (Lebontási Sorrend)

FONTOS: A gyakorlás végeztével a függőségek miatt kizárólag az alábbi sorrendben töröld az elemeket, nehogy felesleges költségek keletkezzenek a fiókodban!
  1. Auto Scaling group törlése (Delete)
  2. Load Balancer törlése (Delete ➔ confirm)
  3. Target Group törlése (Delete)
  4. AMI deregisztrálása (Deregister)
  5. EC2 Instance-ok leállítása és törlése (Terminate instance)
  6. RDS Adatbázis törlése (Delete ➔ Írd be: delete me ➔ Ne kérj final snapshot-ot!)
  7. Internet Gateway lecsatlakoztatása és törlése (Detach ➔ Delete)
  8. Subnetek törlése (Delete subnet)
  9. Security group törlése (Delete security group)
  10. VPC törlése (Delete VPC)
